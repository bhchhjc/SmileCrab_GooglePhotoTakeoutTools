## 1. 개요 및 요구사항 분석

사용자가 제안한 핵심 개선 요구사항은 다음 4가지 축으로 요약됩니다:

1. **상세한 경로 정보 표시**: 단순 앨범명이 아닌 원본 Takeout 입력 경로 및 정리된 출력 디렉토리 경로 명시
2. **계층형 트리 구조 (폴더/앨범 펼치기)**: 앨범을 클릭하여 펼치면 해당 앨범에 속한 미디어 파일 목록을 인라인으로 확인
3. **다양한 조건 검색 및 필터링**: 파일명, 앨범명, 인물명, 날짜 범위(촬영일/작업일), 미디어 유형(사진/동영상), GPS 유무, 변환 상태 등
4. **Before vs After 메타데이터 변환 비교 인스펙터**:
   - 원본 상태 (원본 파일명, 경로, 분리되어 있던 JSON 메타데이터)
   - 변환 과정 (적용된 매칭 규칙, 주입된 EXIF 태그, OS 타임스탬프 동기화)
   - 최종 상태 (정리된 계층 경로, 주입 완료된 메타데이터, 파일 해시)

## 2. 화면 UI/UX 아키텍처 설계 (Master-Detail 구조)

사이드바 네비게이션과 완벽히 조화되는 **좌우 분할(Splitter) 마스터-디테일 레이아웃**을 제안합니다.

│ ▼ 📁 2022년의 사진 (42개)                 │ [선택 파일]: 20220101_123101.jpg                       │

## 3. 세부 구성 요소 설계

### 3-1. 다채로운 검색 및 필터 바
* **통합 검색창**: 파일명, 앨범명, 인물(people), 캡션(description) 실시간 FTS 검색
* **미디어 유형 필터**: 전체 / 사진만 / 동영상만
* **GPS 필터**: 전체 / GPS 보유 파일만 / GPS 없음
* **일자 필터**: 연도/월 선택 콤보박스 또는 최근 작업일 필터

### 3-2. 계층형 트리 뷰 (`QTreeWidget`)
* **최상위 노드 (앨범/폴더 레벨)**:
  - 앨범명 + 총 파일 개수 + 대표 일자
  - 서브 정보: 원본 입력 디렉토리 경로, 정리된 출력 디렉토리 경로 표시
  - 원클릭으로 전체 펼치기 / 접기 지원
* **자식 노드 (개별 미디어 파일 레벨)**:
  - 아이콘(📷 사진 / 🎬 동영상)
  - 파일명, 촬영 일시, 파일 크기, GPS 유무(📍 뱃지), 매칭 상태

### 3-3. Before vs After 메타데이터 비교 인스펙터 패널
트리에서 특정 파일을 클릭하면 우측 패널에 3단계 변환 과정이 명확하게 대비되어 표시됩니다:

| 구분 | 1. 원본 상태 (Before) | 2. 변환 처리 (Transformation) | 3. 최종 상태 (After) |
|---|---|---|---|
| **저장 위치** | Takeout 압축 해제 원본 경로 | 폴더 재분류 규칙 (`YYYY/MM`) | 최종 정돈된 라이브러리 경로 |
| **메타데이터 위치** | `.json` 파일로 외부 분리됨 | JSON 파싱 및 휴리스틱 매칭 | 미디어 파일 내부에 **EXIF로 완전 내장** |
| **촬영 일시** | 파일 시스템 날짜는 다운로드 시점으로 왜곡 | `photoTakenTime` 타임스탬프 추출 | `DateTimeOriginal` 주입 & OS `mtime/birthtime` 복원 |
| **GPS / 위치** | 파일 자체에는 0.0, JSON에만 존재 | GPS 태그 인코딩 변환 | EXIF GPS IFD 주입 완료 |
| **인물 / 태그** | 구글 포토 내부 인물 태그 (`people`) | SQLite FTS 색인 생성 | 로컬 DB에서 인물명 검색 지원 |
| **중복 여부** | 원본 폴더 내 중복 존재 가능 | SHA-256 해시 검사 | 중복 파일 자동 식별 및 보존 |

## 4. 데이터베이스 및 백엔드 보강 방안

현재 `media_files`와 `metadata` 테이블에는 이미 대부분의 비교 데이터(`original_path`, `file_path`, `taken_at`, `file_hash`, `people`, `geo_data`)가 적재되어 있습니다.

추가로 더욱 정밀한 Before/After 추적을 위해:
1. `metadata` 테이블에 **`json_path`**(매칭된 원본 JSON 경로)와 **`match_type`**(매칭 방식: exact, supplemental 등) 컬럼을 선택적으로 기록하거나,
2. UI 인스펙터에서 `original_path`를 참조하여 원본 메타데이터/JSON 정보를 실시간 비교 표시하도록 구현할 수 있습니다.

## 5. 단계별 구현 계획

1. **Phase 1: DB 조회 쿼리 확장**
   - 앨범 단위로 묶인 계층 데이터와 개별 파일 상세를 한 번에 가져오는 집계 쿼리 구현 (`MediaRepository.get_hierarchical_history()`)
2. **Phase 2: 트리 뷰 및 다중 검색 필터 바 구축**
   - `QTreeWidget` 기반 계층 트리 구현
   - 검색어 + 미디어 유형 + GPS 복합 필터 연동
3. **Phase 3: Before/After 비교 카드 인스펙터 컴포넌트 개발**
   - 3단 카드 형태의 시각적 비교 뷰 (`MetadataCompareWidget`) 구현
   - 원본 JSON 내용 보기 팝업 및 Finder/탐색기 열기 액션 연동
4. **Phase 4: 단위 테스트 및 빌드 검증**
